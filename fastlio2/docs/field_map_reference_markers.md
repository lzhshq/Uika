# 真实场地 Map 基准与标识物方案

本文记录真实障碍赛场地中建立稳定 `map` 坐标系的方法。目标是把 FAST-LIO 每次建出的临时 `lidar_odom` 坐标，对齐到一个固定的比赛 `map` 坐标，便于后续规划、标点和策略切换。

## 当前推荐 Map 定义

当前 FineNav 障碍赛配置采用以下 `map` 定义：

```text
原点：T 字形台阶最高平台中心
+x：朝高墙方向
+y：朝大斜坡方向
z=0：最高平台中心高度
主地面：约 z=-0.40
```

因此真实场地中也建议沿用这一套定义：

```text
最高台阶中心 = [0.0, 0.0, 0.0]
主地面       = z=-0.40 左右
高墙方向     = +x
大斜坡方向   = +y
```

## 为什么需要标识物

FAST-LIO 建图时的原点和朝向通常取决于机器人启动时的雷达/IMU 位姿。每次启动、建图或重定位时，原始 PCD 坐标可能并不等于比赛 `map` 坐标。

标识物用于建立对应关系：

```text
FAST-LIO lidar_odom 坐标 -> 比赛 map 坐标
```

有了这个变换后，可以把 PCD、机器人定位、任务点、障碍区域统一到稳定的比赛 `map` 下。

## 规则约束

根据《2026 年仿生足式机器人挑战赛-V2.0》规则，障碍赛场地内允许设置标识物，但需要满足：

```text
尺寸不超过 500mm x 500mm x 200mm
比赛后立即拆除
标识物不能具备控制、通讯、传感、运动等功能
类型、位置、尺寸、功能等必须经过裁判认可
```

任务赛场地内不允许参赛队设置任何标识物。

因此推荐使用无源、低矮、几何形状明显的标识物，不使用 UWB anchor、主动灯塔、主动 LED 信标等带电子功能的设备。

## 推荐标识物

第一版建议使用 3 个无源低矮圆柱，4 个更稳。

```text
数量：3 个起步，4 个更好
形状：圆柱或方块
高度：150~180mm，必须小于 200mm
直径/边长：100~150mm
颜色：黑白高对比，或与场地颜色明显区分
功能：无控制、无通信、无传感、无运动
```

推荐圆柱方案：

```text
底座：薄板，防倒
主体：直径 100~120mm 圆柱
高度：约 180mm
表面：黑白竖条纹或白色高对比外壳
顶部：可贴十字，便于人工点中心
```

低矮圆柱适合 MID360 点云检测，后续可以通过点云聚类或圆柱拟合得到中心。

## 放置方式

3 个标识物不要共线。建议都放在主地面上，不要放在台阶顶面，也不要阻挡机器人路线。

示例：

```text
A：起点附近，放在主地面上
B：沿 +x，即朝高墙方向，离 A 1.5~2m
C：沿 +y，即朝大斜坡方向，离 A 1~1.5m
```

在当前 `map` 定义下，可以类似这样设定：

```text
A_marker = [0.5, 0.0, -0.40]
B_marker = [2.0, 0.0, -0.40]
C_marker = [0.5, 1.5, -0.40]
```

其中 `z=-0.40` 表示标识物位于主地面。实际坐标应以现场测量为准。

## 坐标确定流程

1. 人为固定比赛 `map` 定义：

```text
最高台阶中心为原点
+x 朝高墙
+y 朝大斜坡
z=0 为最高台阶中心高度
```

2. 放置 3 个或 4 个标识物，并用尺子量出它们在比赛 `map` 下的坐标：

```text
A_map = [0.5, 0.0, -0.40]
B_map = [2.0, 0.0, -0.40]
C_map = [0.5, 1.5, -0.40]
```

3. 用 FAST-LIO 建图，得到原始 `lidar_odom` 坐标下的 PCD。

4. 在 RViz 中点选标识物中心，或用点云聚类自动检测标识物中心，得到：

```text
A_odom
B_odom
C_odom
```

5. 用两组对应点求 `lidar_odom -> map` 变换。

6. 用该变换把整张 PCD 转成比赛 `map` 坐标。

7. 后续所有任务点和区域都在转换后的 `map` 中标注：

```text
entry
exit
required_points
mandatory_zones
zone polygon
```

## 变换计算思路

第一版建议只做 2D 平面配准加高度偏移：

```text
x/y/yaw：由平面控制点求解
z：用地面高度或控制点高度求 offset
```

若用 A、B 两个点确定主方向：

```text
v_odom = B_odom_xy - A_odom_xy
v_map  = B_map_xy  - A_map_xy

yaw = atan2(v_map.y, v_map.x) - atan2(v_odom.y, v_odom.x)
t_xy = A_map_xy - R_yaw * A_odom_xy
```

任意点转换：

```text
P_map_xy = R_yaw * P_odom_xy + t_xy
z_map = z_odom + z_offset
```

第 3 个点用于检查误差和镜像方向。如果有 4 个或更多控制点，可以用最小二乘拟合，鲁棒性更好。

## 第一版落地建议

最小可行流程：

```text
1. 准备 3 个无源黑白低矮圆柱
2. 放到起点附近且不阻挡路线的位置
3. 量出 A/B/C 在比赛 map 下的坐标
4. FAST-LIO 建图
5. RViz 手动点 A/B/C 的点云中心
6. 脚本计算 lidar_odom -> map
7. 脚本转换 PCD
8. 在转换后的 map PCD 上标任务点
```

后续可以把第 5 步从“RViz 手点”升级为“点云自动检测圆柱中心”。
